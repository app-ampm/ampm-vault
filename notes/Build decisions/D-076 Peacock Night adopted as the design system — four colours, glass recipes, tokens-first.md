# D-076 Peacock Night adopted as the design system — four colours, glass recipes, tokens-first

## Context

AMPM approved **Peacock Night** as the visual system for every surface (public website, hotel discovery, client portal and app, admin workspace, team app, guest RSVP). The designer's handoff (README, token drafts, 82 HTML artboards) arrived on 7 November 2026 and is now kept in the repository at `reference_docs/design/peacock-night/`. The codebase still carried the bootstrap's plum palette (Fraunces, Source Sans 3, light and dark schemes, drop shadows, four status hues).

## Decision

Peacock Night replaces the plum palette everywhere, implemented tokens-first:

- **Four colours only** (midnight `#0E1534`, peacock `#138A85`, gold `#DDB861`, pearl `#F1EBDD`) as the same semantic CSS variables, so existing classes keep working; every other value is one of the four at an opacity step from `packages/tokens/src/opacity.ts` (the whole tint vocabulary: Tailwind v3 drops any other `/n` silently). Dark only: both scheme slots hold the same values.
- Status hues retired: `success`, `warning`, `danger`, `info` now name the StatusChip treatments (peacock solid, gold soft, gold solid, pearl outline; plus `neutral` pearl 8% and `brand` peacock glass); the word in the chip carries the meaning.
- **Glass instead of shadows**: three recipes (base, peacock, gold) in `glass.ts` and `GlassPanel`; the web blurs with `backdrop-filter`, iOS layers an expo-blur `BlurView` under the fill, Android and Reduce Transparency draw opaque fallbacks; only top-level panels blur. Rims (`shadow-rim*`) and the focus halo (`shadow-halo`) are the only shadows. Glow orbs from `glow`.
- **Type**: Gilda Display (one weight, never synthesised), Manrope (data in `tabular-nums`, the retired mono), Rozha One for Devanagari greetings; expo-font in the Expo app, next/font on the site.
- **The contrast gate became data**: `contrastPairs` lists every text-on-fill pair the system uses, each held to 4.5:1 unless it documents an exception (D-077).
- **Two presets**: `tailwind.preset.cjs` for the Expo app (its font families also under `extend`, which fixes NativeWind's system-font override of `font-sans` on native) and `tailwind.preset.web.cjs` for the Next.js site (families through next/font variables, the `web:` variant), so the site reuses the library's class recipes via `@ampm/ui/styles` without React Native.
- **The library is the kit**: `packages/ui` restyled and extended (GlassPanel, GlowBackdrop, Screen, ScreenHeader, TabBar, NavRail, SegmentedControl, FilterChip, Toggle, Checkbox, OtpInput, Badge, Avatar, ProgressBar, Stepper, Stat, ListItem, InternalPanel, OfflineBanner, PhotoPlaceholder); screens compose it instead of hand-rolled markup.
- **A class audit** (`packages/config/tailwind/class-audit.mjs`) fails lint when a class is not generated by the presets on web or native.
- The guide `docs/design/peacock-night.md` maps tokens to classes, components to the spec, and each artboard to its route (built, reskinned or next).

## Alternatives considered

- Swapping only the token files (the handoff's suggestion): keeps the old components' shadows, light scheme and status colours, and the pre-blended opaque tints cannot express glass. Rejected.
- Adding the four colours as palette classes (`bg-gold/14`): breaks the semantic-names rule and every existing class. Rejected for opacity steps on the semantic tokens.
- `@fontsource` packages on the site instead of next/font: no network at build time, but the styling rules name next/font. Kept next/font with a web preset.

## Consequences

- Every new screen follows the guide and the artboard; the rules files (`styling.md`, `ui.md`) and CLAUDE.md point there.
- A tint outside the opacity steps, or a retired class, fails lint (class audit) instead of rendering nothing.
- expo-blur is a new native dependency of the Expo app (and a peer of packages/ui).
- Screens for features not built yet (wedding home, approvals, RSVP, team app consoles) are designed but not coded; they are built from the kit when their sprint comes.
