## Narrative

**Asked:** implement the approved Peacock Night design system (designer handoff in ~/Downloads, now kept at `reference_docs/design/peacock-night/`), customise the component library to it, rebuild the existing frontend, and leave it ready for the screens still to come.

**Decided (with why):**
- Peacock Night adopted tokens-first ([[D-076 Peacock Night adopted as the design system — four colours, glass recipes, tokens-first]]): four colours only, as the same semantic CSS variables plus an opacity-step vocabulary (Tailwind v3 drops any other `/n` silently), glass recipes instead of drop shadows, Gilda Display / Manrope / Rozha One, dark only. The contrast gate became data (`contrastPairs`).
- Midnight on peacock measures 4.25:1, not the 4.5:1 the handoff claimed: kept as approved with a documented exception, pending AMPM's call on `#148F8A` (4.53:1) ([[D-077 Midnight on peacock at 4.25 to 1 kept as approved, pending AMPM's call on 148F8A]]).
- App shell ([[D-078 App shell — floating tab bar on phones, staff rail and client top bar from 768, areas from policy grants]]): screens own the floating tab bar, the layout draws the staff rail or the client top bar from 768, staff areas come from `@ampm/policy` grants.
- The Next.js site gets its own preset (next/font variables, the `web:` variant) and reuses the library's class recipes through `@ampm/ui/styles`.

**Built:** tokens and both presets; fonts in both apps; the `packages/ui` kit (restyled Button, Input, StatusChip, Card, Callout, Sheet, Toast, states; new GlassPanel, GlowBackdrop, Screen, ScreenHeader, TabBar, NavRail, SegmentedControl, FilterChip, Toggle, Checkbox, OtpInput, Badge, Avatar, ProgressBar, Stepper, Stat, ListItem, InternalPanel, OfflineBanner, PhotoPlaceholder, QueryErrorState); every existing Expo screen rebuilt to its artboard (sign-in, account, field notes, portal, hotels, consultancy, sales, hotel-team queue and forms); the website W1–W8 plus privacy/terms placeholders; one date formatter in `@ampm/core`; the class audit (`packages/config/tailwind/class-audit.mjs`) wired into lint; the guide `docs/design/peacock-night.md` and the rules in `.claude/rules`. Work ran as three workflows (kit, screens, polish), each with independent reviews and a fix pass.

**Fixed along the way:** `font-sans` rendered the system font on iOS/Android (NativeWind's extend outranked the tokens); data text lost tabular digits on native; react-native-web dropped `accessibilityState` (now `aria-*`); the React Compiler froze the signed-in check so the chrome never appeared after sign-in in a compiled build (now `useSyncExternalStore`, and the mobile Jest suite compiles with the compiler).

**Verified:** `pnpm check` 28/28 (API database tests on an isolated `ampm_peacock_test`); browser pass against the mocks at 390 and 1280/1440 (client and staff, website pages, a synthetic enquiry from the site's form reaching the staff pipeline); native iOS simulator (fonts, real blur, tab bar).
