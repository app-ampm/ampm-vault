Read-only status check: the user asked for the state of the mobile apps and the locked decisions behind them. Nothing in the code changed.

**Status on main (42661d2, 20 Nov 2026).** Neither the iOS nor the Android app is in a store; this is unchanged since the 15 Nov check. One Expo codebase (`apps/mobile`, Expo ~58.0.19, React Native 0.88) builds iOS, Android and the browser; CI's `mobile` job exports all three bundles (`bundle:check`) on every PR that touches the app, and only the browser build is live at app.ampmverse.com. `app.json` still has no `ios.bundleIdentifier` or `android.package`, there is no `eas.json`, development build, push-notification or OTA-update package, and no record of an Android run (iOS ran in Expo Go on the iPhone 17 Pro and iPad simulators). The Cognito leftovers (`aws-amplify`, `@aws-amplify/react-native`, `src/lib/amplify.ts`, `src/lib/cognito-auth.ts`) are still in the app after D-142 retired Cognito; D-142 leaves their removal to a later PR.

**Locked decisions listed for the user.** AMPM: Q1 (native iOS and Android, offline wedding-day use with sync and conflict handling), tablets (both apps on iPad and Android tablets), R4 (client portals also in the browser), R10 (staff password + authenticator, clients mobile OTP), R17/Q10 (the whole first release in one launch); the 26 Oct answers are still marked for AMPM's countersignature. Engineering: D-013, D-017, D-018, D-021, D-026, D-030, D-076, D-078, D-129, D-142 (replaces D-112), D-147.

**Open, and blocking a store release.** Apple and Google developer accounts in AMPM's name (risk question K6, unanswered); web-first for clients versus both native apps together (K7, unanswered); one store app or two (the decisions name a team app and a client app, the code is one app with areas by grant, D-078); app IDs, `eas.json` and a development build; `docs/planning/production-readiness.md` has no item for the native apps or store review.

**Native build setup (D-152), on the user's go-ahead.** The user decided one store app for staff and clients and the app id `com.ampmverse.app`. Built on branch `feat/native-builds` (commit 2842f68, not pushed as a PR yet): the app ids and `ios.supportsTablet` in `app.json`; development and preview variants (`.dev`, `.preview`) in `app.config.ts` from `APP_VARIANT`; `eas.json` profiles (development, development-device, preview, production; Node 24.22.1 with corepack); `expo-dev-client`; the `ios`/`android` scripts run the development variant natively with Metro on 8082, and `native:prebuild` regenerates the never-committed native projects (ESLint now ignores them).

The first real builds found two blockers. Android failed in `@nozbe/watermelondb` 0.28 (its Java reads a `BuildConfig` that AGP 9 no longer generates); it was D-026's rejected, never-imported comparison arm, already listed for removal, so it went. iOS built but crashed at launch (dyld: ExpoVideo's precompiled framework needed a symbol missing from ExpoModulesCore 58.0.26): the app had drifted behind SDK 58's patches, so the 18 runtime packages `expo install --check` flagged moved to their expected versions (expo 58.0.26, React Native 0.88.1), `packages/ui` in lockstep, jest-expo 58.0.15; the Jest 29 to 30 major is left for its own change. Verified on the iPhone 17 Pro and iPad Pro 13-inch simulators (native tablet layout) and the Pixel 7 emulator, signing in against a local API on throwaway databases `ampm_native` and `ampm_native_test`; the web build too; `pnpm check`, `format:check`, `bundle:check` and the scans green.

Still open (production-readiness §4 "Native apps"): an Expo account for AMPM (this Mac's Expo CLI is signed in to 32dentaldesign's account, which must not hold AMPM's project), the Apple and Google accounts in AMPM's name, store listings, a reviewer sign-in, AMPM's app icon (still Expo's template), push notifications, export compliance, and the Cognito removal before the first store build.

**Merged (20 Nov 2026, 19:12 UTC).** PR #165 squash-merged as `ce239eb` once CI was fully green. The first run failed only `infra`, in the monitoring smoke test (`infra/scripts/smoke-monitoring.sh`): it reads `sum(prometheus_rule_group_rules)` once, about 16 s after start, while Prometheus scrapes itself every 30 s, so it can see 0 rules. That is a timing race unrelated to the PR (no `infra/` change; the job ran because `pnpm-lock.yaml` is in its trigger paths), and the re-run passed. GitHub auto-merge is disabled on the repository and `main` is unprotected, so the merge was done by hand.
