## Narrative

Side session started from the production-readiness session to clear two hygiene items of `docs/planning/production-readiness.md` §4 left by the 20 Nov cutover. Built on branch `fix/api-worker-graceful-shutdown`, cut fresh from `origin/main`. PR [#157](https://github.com/app-ampm/ampm-platform/pull/157), decision [[D-146 The API and worker stop gracefully  connections close after the drain, under an init|D-146]].

**What held shutdown.** Reproduced with the local Compose stack (Docker Desktop had to be started; it gives containers a 1 s stop timeout, so the before-run used `-t 10`). Both api and worker were SIGKILLed after 10 s (exit 137). A diagnostic preload listed the handles left after SIGTERM: Nest's hooks had run, and one Redis socket stayed open in each process. It belonged to the rate-limit store (`RedisRateLimitStore.fromUrl` in `PolicyModule`), which nothing ever closed. Node is PID 1 in the container, so the SIGTERM Nest re-raises after its hooks is ignored and the process waits for that socket until the SIGKILL.

**What was decided and built.**
- The store closes its client in `onApplicationShutdown` (QUIT, else `disconnect()`).
- Prisma and `JobQueue` move from `onModuleDestroy` to `onApplicationShutdown`, which Nest 12 runs after the HTTP server has drained. A new Redis-backed test showed the old order was a second hang: Prisma disconnected first, reconnected for a request in flight and left that pool open.
- api and worker get `init: true` and `stop_grace_period: 30s` in the production, staging and local Compose files.
- `apps/api/src/app-shutdown.redis.spec.ts` boots the real app against Redis and PostgreSQL. It asserts that no TCP handle is left after `app.close()` for the worker and the API, that a request in flight gets 200, and that the queues close before Prisma. It fails on the old code. CI's Redis step now runs every `*.redis.spec.ts`.
- `openssl` is installed in both Dockerfile stages.

Verified locally: the stop takes 0.28 s with exit 143 (exit 0 within 15–28 ms when the re-raise is blocked, so nothing is left open); a request in flight inside the api container during `docker compose stop` was answered 200 with the database up before the exit; and the image build and `migrate deploy` show 0 Prisma OpenSSL warnings (4 before). `pnpm check` (with a disposable PostgreSQL 16 and `DYNAMIC_ROLES=true`) and `pnpm format:check` are green.

**What remains.** Merge #157 once CI is green, then a normal production deploy (`production-setup.md` §4). That deploy's own stop of the old containers still ends in 137, because the old image has the leak. A keep-alive connection that had a request in flight lingers up to ~6 s after its response, which is within the grace period.
