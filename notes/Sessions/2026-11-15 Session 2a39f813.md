## Narrative

The user, testing hotel discovery on app.ampmverse.com, could not edit the next proposal after revising one. They also asked for a less cluttered staff enquiry screen that shows which client sent each enquiry and gives a clear pipeline for making and tracking proposals.

**Cause of the edit bug.** The API has always had a draft-only `PATCH /consultancy-admin/proposals/:id`, but the app never called it. There was no api-client hook and no edit control, so a revised draft could only be shared as it stood. The fix adds `useUpdateProposal` and a `ProposalEditForm` that opens on the saved draft. The new and edit forms share their fields. A draft now offers "Edit draft" beside "Share version N", and "Revise as version N+1" opens the new draft straight in the editor. Earlier versions fold away, and "New proposal" only shows while no version stands.

**Client names and pipeline.** The staff enquiry view now carries `accountName`, `hotelName` and `latestProposal`, read in batched lookups by a new `EnquiryInsightsRepository`; the name reads extend the D-063 shortcut. `@ampm/core` gains `hotelEnquiryStage` (six stages over the ten statuses). The list filters by `stage`, and a new `GET /consultancy-admin/enquiries/pipeline` counts each stage. The queue leads each card with the client and tags the newest proposal, with stage chips and counts above it. The enquiry page now has a pipeline stepper, a next-step callout and four tabs (Overview, Proposals, Activity, Booking) in place of one long scroll. The design is recorded in [[D-130 Staff enquiry queue tracks the pipeline by stage, names the client and edits draft proposals in place]].

The whole flow was checked in a local browser against the dev API (revise, edit, save, share; phone and desktop). `pnpm check` covers the new API, core and app tests. Because the response contract changed, the deploy is API-first. Still open: the stage filter is not in the URL yet, and the name reads should move to a shared directory accessor along with D-063.

Follow-up in the same session: #139 was merged as `c84b340` and deployed API-first, then verified live in the user's Chrome. The user then asked for sharing a proposal to move its enquiry to client decision automatically. Before, that happened only from `proposal_received`, and only for HT or an assigned PM; Super Admin shares never moved it. The share now walks any open pre-decision enquiry along legal §7 edges to `client_decision`, with one client notice. The share's own permission covers the move, so the per-role mover rule is not checked again ([[D-131 Sharing a proposal moves its enquiry to the client's decision]]). The transition write moved into a shared `EnquiryTransitionWriter`.
