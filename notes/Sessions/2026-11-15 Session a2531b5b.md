## Narrative

The user reported that on app.ampmverse.com every first click on a tab, panel or button flashed white before the screen appeared, and asked for smooth loading and scrolling, with skeletons, spinners or button loaders wherever needed.

**Diagnosis, measured rather than guessed.** A frame sampler in the live page (25 points per animation frame, looking for a light opaque background) showed that every first visit to a staff area painted a full-window `rgb(242, 242, 242)` layer for about 285 ms, and Hotel enquiries for about 665 ms because `/enquiries` redirects to a second route. The layer was React Navigation's per-screen `Background`, painted in its light `DefaultTheme` because the app never set a navigation theme. It was visible because Expo Router 58 splits every web route into its own chunk by default. Each loads through `React.lazy` behind a Suspense fallback that renders nothing in production, held for React's ~300 ms reveal throttle even when the chunk is cached. The chunks were 1 to 61 KB each against a 5.35 MB shared bundle, so splitting bought nothing.

**Fix ([[D-129 Web export loads every route up front and the navigator paints no light background]]).** `asyncRoutes: false` in app.json puts every route in the main bundle, so navigation never suspends. A Peacock Night navigation theme (`navigation-theme.ts`, tokens for ink and accent; background transparent on the web, midnight on native) now wraps both `AppStack` variants. The lead activity timeline got a skeleton in place of an empty space while loading. A survey of the mutation buttons found the loaders already wired almost everywhere (FormCard, sheets, export, subscribe, sign-in), and screens already use skeletons, so nothing else was churned.

**Evidence.** On a local production export in the same Chrome window with real clicks: 0 light frames out of ~73 per navigation across six staff areas and three client tabs, against 18 to 37 on the live box. Scrolling was already 60 fps (p95 17.6 ms) before and after; the felt jank was the transition flash. Cost: about 0.7 MB more uncompressed JS on first load (roughly 150 to 200 KB gzipped), cached afterwards.

**Shipped.** PR #137 (`fix/web-smooth-loading`, rebased onto main `98c724c`), `pnpm check` green locally (1,007 mobile and 659 UI tests). Front-end only, so a `deploy-web.sh` from merged main is all the box needs.

**Deployed.** On the user's go-ahead, #137 was squash-merged once CI was green (`dcc6548`, main tip). The web export was built from merged main (`EXPO_NO_DOTENV=1`, one 6.1 MB entry, 1.14 MB gzipped) and synced to the box's httpdocs, keeping `.htaccess`, `.htpasswd` and `.well-known/`. The API was untouched and the box still runs `98c724c`. Verified on live in the user's Chrome on a fresh load, with real clicks: 0 light frames on the first visit to all seven staff areas and on opening a lead card, at about 60 fps.
