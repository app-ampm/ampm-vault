## Narrative

Ran the sprint 2 offline spike (build-plan §11.4) and chose the team app's offline store: **plain `expo-sqlite`
with our own change queue** (D-026, accepted), over WatermelonDB and PowerSync. Only expo-sqlite runs in Expo Go;
offline.md's prescriptive rules (idempotency on client id + base version, replay order, server-wins-on-status, a
conflict log) map directly onto our own queue, so the sync libraries' engines add nothing while costing a
development build — and, for PowerSync, a self-hosted service container under R13/G2's single VPS plus an FSL
non-OSI licence. Full comparison in `docs/engineering/offline-spike.md`; standards §2.6 updated.

Built, behind the real pipeline: a stand-in "field note" mutation end to end — a Zod contract plus pure
queue/idempotency/uuidv7 logic in `packages/core` (unit-tested); an `apps/api` spike module (in-memory, idempotent
on `(id, baseVersion)`, server-wins conflict, behind the Auth + Permission guards using the `tasks.incidents` key,
unit-tested); and an `apps/mobile` feature with one `OfflineStore` interface on expo-sqlite (wired into the app)
and on WatermelonDB (type-checked comparison arm, never bundled), reading local-first, queueing offline writes,
replaying in order, and showing offline state + the pending count from `packages/ui`. Verified in the iPhone 17
Pro simulator (Expo Go): with the API stopped (the documented "unreachable" method, since the simulator has no
airplane mode), a recorded note shows pending; on restart + Sync it reaches the API exactly once (server list is
one record at v1). `pnpm check` green (27/27).

Remains: this is a spike. Before the real feature ships, remove the `SPIKE STAND-IN` artifacts (the
`@nozbe/watermelondb` dependency and `watermelon-store.ts`, the `apps/api` spike module, the `field-note` contract,
the `/field-notes` route and screen), keeping the queue/idempotency logic and tests; add the development build for
SQLCipher at-rest encryption; build the real role-scoped store. Not merged to main (the developer merges).
Flagged separately: `apps/api/src/common/zod.ts` `ZodBody`/`ZodParams` fail at runtime (never exercised before) —
the spike used NestJS `@Param`/`@Body` with explicit `.parse()` instead.
