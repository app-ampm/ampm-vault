## Narrative

The developer asked that the admin can see each client's complete wishlist: the hotels a client on the ₹50,000 hotel-discovery plan saves while exploring, so the team can track what clients are interested in. The permission matrix already granted the read (§5.3 "Saved hotels (created by clients)": SA, SM, HT read; PM on assigned weddings), and the TW-13 wireframe already named a Hotels region on the client hub. Only the route and the screens were missing.

Built ([[D-154 Staff read clients' saved hotels  one list route, a panel on the client hub and an all-clients screen|D-154]]):
- `GET /hotels-admin/saved-hotels` uses the existing `hotels.saved_hotels.read` key. It is read-only and cursor-paginated, newest first, with an optional `accountId`. It never returns demo accounts or removed saves, and selects no restricted hotel column.
- A "Saved hotels" panel on the client hub sits between subscriptions and hotel enquiries; a row opens the hotel's catalogue profile.
- A new all-clients "Saved hotels" screen at `/leads/saved-hotels` is linked from the Clients list header; a row opens the client's hub.

Project Managers are refused on the route today, following the service-agreements precedent: an assigned-wedding grant has no wedding on the route until module E. The repository already scopes such a grant to the PM's weddings.
