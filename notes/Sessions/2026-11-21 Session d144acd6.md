## Narrative
A side session started from [[2026-11-21 Session 2c39eb17]] (PR #170, D-154) to give the Hotel team (HT) a way into clients' saved hotels and to show per-hotel interest. Built on #170's head while it was open, then replayed onto `origin/main` once it merged as `0fcc5f7`. Result: **PR #171** (`feat/hotel-saved-by-clients`), recorded as [[D-155 The Hotel team reaches clients' saved hotels from the catalogue, and a hotel's page names the clients who saved it|D-155]].

**Built.**
- The Hotel catalogue header links to `/leads/saved-hotels` ("Saved by clients"), gated on `can()` for `hotels.saved_hotels.read`.
- `GET /hotels-admin/saved-hotels` takes an optional `hotelId` (core query, repository `where`, api-client path), with the same scope: live rows, no demo account, no removed save.
- The hotel's details page (`/hotels-admin/[hotelId]/details`) has a "Saved by N clients" panel in T5's side column under the contacts. Each row shows the client's note and the day saved, and opens the client hub.
- Six new e2e cases for the filter, Jest tests for the panel, the link, the permissions hook and the HT hub. `pnpm check` is green.

**Decided and why.**
- The brief said HT lacks the Leads area. The matrix says otherwise: HT reads `crm.leads.read` and `crm.accounts.read`, and `staffHomeHref` lands HT on `/leads`. So rows keep opening the client hub, and D-155 corrects D-154's line. Checked as Hema (HT) in the web build: catalogue → saved hotels → hub (read-only) → hotel details panel. Also checked against the API with an HT token.
- The heading counts the loaded page with a "+" floor instead of a new total field, so the page contract stays unchanged.

**Remains.**
- CI and merge of #171.
- The API-first redeploy before the web build: an API with only #170 silently ignores `hotelId` (non-strict query) and the panel would then list every client's saves.
