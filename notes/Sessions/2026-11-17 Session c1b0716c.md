## Narrative

Started from the [[2026-11-17 Session a7d855da|hotel discovery workflow session]] to close the last gap in inviting a client on the test box. Sales could convert a lead and #148 made `/activate?token=…` work under the local identity provider, but the box runs the console email adapter, so the activation link never reached anyone.

**Decided ([[D-137]]):** test builds hand staff the invited contact's link instead of logging it. Printing it from the console adapter would need SSH to read and would put a live credential in application logs, and that adapter is the fallback for any unconfigured channel, including in production. Real email needs a provider decision (and SES is a paid AWS service), so it stays with the go-live work. The route is `POST /crm/accounts/:accountId/contacts/:contactId/invite-link`, under `/crm` because the box keeps `/_api/auth/dev-login*` behind Basic-Auth and a staff Bearer there trips fail2ban (#147). Only the token's hash is stored, so the endpoint reissues the invite (retiring earlier links) and returns the URL, audited on the contact without the token. It is gated exactly like the dev sign-ins, a 404 before any lookup outside a local, non-production build; that gate is now shared as `apps/api/src/identity/dev-gate.ts`.

**Built (PR #150):** the contract `accountContactInviteLink`, the hook `useAccountContactInviteLink`, the service and controller, and "Get invite link" on the client hub's contact sheet (selectable link; Copy link on the web through `copy-text.web.ts`, as native has no clipboard module and none was added). Tests: e2e convert → link → dev invite sign-in → activate → `/me`, plus refusals; unit tests for the gate and its order. An independent pre-merge review found no blockers; its test gaps, the in-transaction status read and the UI's vanishing link were fixed.

**Shipped:** PR #150 squash `bb2c0af`, merged with CI green, then deployed API first (`redeploy-box.sh`, no migrations) and then the web (`deploy-web.sh`); the box `.deployed-commit` is bb2c0af for both tiers. Verified on the box over SSH: convert a lead with an email → link → dev invite sign-in → activate → `/me` shows an active client; a second link after activation is a 409. The same UI was verified end to end in a local web build; the live click-through needs the site's Basic-Auth in the user's browser.

**Remains:** a contact who already activated still sees the card (the staff contact view has no login status; the API answers 409). From #148, the token travels in the link's query string, so the web server's access log holds it until it is used; a `#token=` fragment would avoid that.
