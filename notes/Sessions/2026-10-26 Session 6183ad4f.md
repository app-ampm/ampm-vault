## Narrative
The knowledge graph was refreshed so that it covers the round-two review questions. It had been built before `docs/review/remaining-questions.md` existed, so nothing in it knew about R1 to R19; `graphify query` on the subject returned the old Q nodes and the session-journal script, which is the failure this refresh exists to prevent.

The run went through the skill rather than headless `graphify update`, because this repository is mostly prose: the semantic pass needs a model, and a headless re-cluster would have thrown away the sixty-four curated community names. Four documents and two scripts were re-extracted by three subagents and the AST pass. The scope grew while the run was in flight — the session that started this one added a short one-page version of the questions (Part A8), a `--short` mode and `docs/tools/pdf_build.py` at 12:36 to 12:40, after the first extraction had already read `docs/README.md`. The skill's coverage gate caught it (README had grown from 138 lines to 145 since it was read), so the changed set was re-detected and a third agent covered the new short document and README's current state. The single pointer sentence the long questions document gained at line 17 was read directly and added as one edge rather than paying another 140,000 tokens to re-read a 46 KB file for 205 bytes of change.

Two losses were caught by graphify's export guard and repaired, which is the substance of [[D-010 A graph refresh keeps nodes a re-extraction does not reproduce]]. `decision-brief.md` entered the changed set for a one-sentence edit, and replace-on-re-extract dropped the thirty-four principle, section and journey nodes the committed graph held for it, because the fresh extraction read the file as per-question nodes instead; those nodes and their 179 edges were re-added, so both granularities now coexist. A duplicate id minted for "Recording a confirmation from AMPM" was collapsed onto the established one, since `docs/wireframes.md` and the root README carry edges into those ids.

The graph now holds 1,813 nodes and 5,438 edges in 68 communities, up from 1,660 and 5,055 in 64. All nineteen R questions are nodes in both the long and the short document, each short question linked to its full counterpart, and the questions carry references back to the Q numbers, audit findings and assumptions they came from. `docs/tools/graph_labels.py` carried fifty-five names over the re-clustering; thirteen communities were named by hand, among them "Round-Two Open Questions (R1 to R19)". Health check reports no dangling, missing or collapsed edges, every community has a real name, and the refreshed `graphify-out/` is committed as 91b789b.

What remains: nothing for the graph itself. The six changed documents and scripts are still uncommitted work belonging to the session that started this one, and the checkpoint hook commits them at the end of the turn — the graph describes them as they stand on disk now, so any further edit to those files wants another `/graphify . --update`, which is cheap now that the extraction cache holds all four documents. Ten pre-existing id collisions on whole-document nodes were left alone; they cost a label, not an edge.
