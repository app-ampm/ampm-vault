## Narrative

Audit only (no change to code or the box): can the shared Plesk test box (31.97.62.74, app.ampmverse.com) be promoted to production as it stands? Verdict: **not in its current state**. D-106 already chose this box for production, but D-015's condition (a box dedicated to AMPM, Indian datacentre) is unmet: it is shared with n8n (public on :5678), valhalla and verifyfort-mongodb, and the datacentre is unconfirmed. Live findings, 15 Nov 2026: **no database backup exists**. The running Postgres has `archive_mode=off` (started 5 Nov, never restarted after the conf went back to `on`), pg_stat_archiver shows 0 archived, the pgbackrest service isn't running, its repo volume is empty, and no cron runs backup-media.sh. Postgres uses the committed dev password, Redis has no password, and the pgBackRest cipher is the committed smoke value (the repo is public, D-086). The box runs `NODE_ENV=development` with `IDENTITY_PROVIDER=local`, so dev-login, guarded only by the shared Basic-Auth password, can mint a super-admin token. env.ts gates still open: identity (client OTP unbuilt), bot check (stub), email (console, no SMTP), and the D-106 storage flags not applied on the box. Razorpay is in TEST mode. There is no Sentry or uptime monitor, `StubAvScanner` is wired unconditionally (it would run live once D-106 opens local storage in production), privacy and terms are placeholders, and the DB holds seed or tester data only (14 users, 4 hotels). Recommended order: fix backups first, settle the dedicated-vs-shared question, then a staff-first Cognito go-live, then clients once OTP and DLT land. No decision taken. Side effect: an `alpine:latest` image pulled for a read-only volume listing was removed again.

**20 Nov 2026 — production on the same server.** The re-audit found a live incident. Since 19 Nov 08:51 UTC the test stack's Postgres had been crash-restarting every ~10 s, about 7,400 times. Archiving switched on at the 17 Nov restart, but the pgBackRest stanza never existed, and the async archive-push orphan was reaped by the postmaster (PID 1), which counted its exit as a crashed backend. It was stopped at 05:49 with `archive_command='/bin/true'`, and a safety `pg_dump` was taken. The box is confirmed in Mumbai (Hostinger India range, DE-CIX Mumbai upstream). A code-audit agent listed the production blockers on `main`: client OTP missing, staff first sign-in, seed without a production guard, the website's hard-coded bot token, a dev web bundle, Razorpay test keys, the stub AV scanner, placeholder legal pages, plus gaps in rate limits, headers, observability, partitions and secrets in URLs.

**20 Nov 2026 (cont.) — production stack merged; AMPM's own sign-in replaces Cognito.** PR #151 (`c786230`) merged: the production stack on the shared box, init-wrapped Postgres, the secrets helper, the deploy script and the clean bootstrap.

The user asked why Cognito was used. After I compared it with in-app sign-in, pointing to their LMS control plane, which signs people in itself, they chose to switch. That is D-142, built in PR #152:
- staff passwords with Argon2id from Node's own crypto, and RFC 6238 TOTP on Node's HMAC
- secrets encrypted with AES-256-GCM, and recovery codes stored as HMAC
- activation from an invitation sets both the password and the authenticator
- forgot and reset by emailed link, an admin reset that re-invites, and sign-out
- the session opens at sign-in, so a revocation reaches a token that has not been used yet (an e2e test caught this)
- the app's forms are shared with the old Cognito screen
- no new dependencies

An independent adversarial review found 1 high, 2 medium and 6 low issues: a mailbox-only or password-only takeover of accounts without an authenticator; unlimited code guessing; lockout abuse; ILIKE treating `_` as a wildcard in the email match; and others. All were fixed in `8dcbc32` with tests. Tokens in URL query strings are deferred to the readiness tracker.

Still waiting on the user: the Super Admin's email, the SMTP and Turnstile values, and the test-app/test-site domains. After #152 merges come the first production build, the bootstrap and the edge switch.
